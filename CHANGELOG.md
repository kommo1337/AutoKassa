# Changelog

Все заметные изменения в проекте **AutoKassa** будут документироваться в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
и проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

### Добавлено
- Команда «Удалить ожидающую копию и создать новую» в настройках Яндекс Диска: с подтверждением удаляет только производный файл очереди (исходная БД не затрагивается) и сразу выгружает свежий снимок — снятие постоянного конфликта 409 с чужим файлом (раздел 6 аудита)
- В блоке ожидающей облачной копии показываются имя, дата и размер файла очереди, а также время последней неудачной попытки выгрузки
- Поколение подключения `IYandexDiskAuthService.ConnectionGeneration`: выгрузка, завершившаяся после отключения/повторного входа, не инвалидирует вновь сохранённый токен и не фиксирует чужой успех (раздел 6 аудита)
- Интеграционный тест облачной очереди с настоящим `SettingsService` и файловой БД (реальные миграции + SQLite Online Backup API)
- Облачное резервное копирование на Яндекс Диск: выгрузка согласованного SQLite-снимка в папку приложения (`app:/`) через REST API
- Авторизация Яндекс Диска через OAuth 2.0 + PKCE без `client_secret` (общий секрет не встраивается); запрошен только доступ к папке приложения
- Хранение access-token в DPAPI-хранилище (`%LOCALAPPDATA%\AutoKassa\Secrets\yandex-disk-token.bin`, привязка к пользователю Windows)
- Ввод ClientId Яндекс Диска прямо в приложении: диалог открывается по «Подключить» при пустом ClientId, значение сохраняется в профиле пользователя (`%LOCALAPPDATA%\AutoKassa\yandex-disk-clientid.txt`) и имеет приоритет над `appsettings.json`
- Проверка снимка перед отправкой (`PRAGMA integrity_check`), сверка имени/размера/MD5 после выгрузки, повтор неотправленного файла из локальной очереди после сбоев и перезапуска
- Ротация облачных копий: удаление только файлов `AutoKassa_Backup_yyyyMMdd_HHmmss.db` (`type == "file"`) в `app:/` сверх общего лимита `BackupKeepCount` и только после подтверждённой выгрузки
- Координатор автобэкапа `IAutomaticBackupService`: немедленная проверка при старте и раз в час, сериализация запусков, корректная остановка при выходе приложения
- UI «Яндекс Диск» в настройках: подключение/отключение аккаунта, одноразовый код подтверждения, статус облачной копии, дата последнего успеха, «Загрузить сейчас»
- Настройки `AppSettings.YandexDiskBackupEnabled` и `YandexDiskLastBackupUtc` + миграция `AddYandexDiskBackupSettings`; флаг экспортируется/импортируется в JSON, дата успеха — нет

### Изменено
- `ISettingsService`: необязательный `CancellationToken` у backup-методов, новый `SetYandexDiskLastBackupUtcAsync`; после сохранения настроек и подключения Яндекс Диска координатор бэкапа выполняет внеочередную проверку
- Подробности и ограничения облачного бэкапа задокументированы в README и `docs/kimi` (см. TRAPS §3.15–3.19)

### Исправлено
- Ротация облачных копий больше не путает папки с файлами и не трогает файлы с похожими именами: удаляются только ресурсы `type == "file"` с точным именем `AutoKassa_Backup_yyyyMMdd_HHmmss.db` (YD-01)
- Постраничное чтение содержимого `app:/` разбирает реальный ответ API (`_embedded.items`) с контролем полноты по `_embedded.total` — ротация снова видит все копии (YD-02)
- Подключение Яндекс Диска после ошибки OAuth (неверный/просроченный код, сбой сети) восстанавливается без перезапуска: добавлено транзитное состояние `AwaitingCode` и команда «Отмена» ожидания кода (YD-03)
- Повреждённая локальная копия больше не блокирует облачный бэкап навсегда: снимок создаётся во временной папке и попадает в очередь только после проверки целостности, повреждённый файл очереди уходит в карантин `*.corrupt` (YD-04)
- Ошибки чтения метаданных после загрузки обрабатываются по классам: 404 — ожидание появления ресурса после 201/202, 401 — инвалидация токена, 5xx/сеть/таймаут — повторы вместо ложной «проверки целостности» (YD-05)
- Координатор автобэкапа при выходе ожидает и таймерный цикл, и внеочередную проверку: один отслеживаемый worker с объединением повторных запросов (YD-06)
- HTTP-таймауты Яндекс Диска (общий 100 с и отдельный 10-минутный для загрузки) становятся повторяемыми сбоями, а не безмолвной «отменой» операции (YD-07)
- Сохранение токена Яндекс Диска стало атомарным: временный файл с уникальным именем + `File.Replace` через общий помощник `AtomicFile` — сбой замены больше не лишает сохранённый токен (YD-08)
- Постоянный локальный сбой автобэкапа не пропускает облачную выгрузку: локальная и облачная части тика имеют независимую обработку ошибок (YD-09)
- Если браузер не открылся при подключении Яндекс Диска, вход не прерывается: показано предупреждение, добавлена кнопка «Скопировать ссылку» (новый `IClipboardService`) (YD-10)
- Состояние облачного бэкапа в настройках соответствует факту: единый `ApplyCloudState` при загрузке и событиях, уведомление о вычисляемой дате, индикатор очереди сохраняется при отключении (YD-11)
- Добавлен регрессионный тест утечки секретов в логи (токен, код, verifier, Authorization, `error_description`) через собственный Serilog-sink; устаревшее описание в `services.json` актуализировано (YD-12)
- Закрыты рекомендации раздела 5 аудита: общий метод `ISettingsService.CreateSqliteSnapshotAsync` — облачная очередь получает снимок без побочных эффектов локального бэкапа (локальная ротация осталась в `CreateBackupAsync`); дата успеха фиксируется до удаления файла очереди — при сбое её записи pending сохраняется для идемпотентного подтверждения 409 без повторной передачи; комментарий о DPAPI-энтропии приведён к честному threat model
- Закрыты рекомендации раздела 6 аудита: единая обработка HTTP 401 на всех стадиях выгрузки, включая ротацию (токен инвалидируется только при неизменном поколении подключения; успех загрузки сохраняется, статус — `AuthRequired`); при смене подключения посреди выгрузки успех не фиксируется и файл очереди сохраняется для идемпотентного подтверждения
- Создание снимка БД больше не оставляет хендл файла: соединение назначения в `CreateSqliteSnapshotAsync` открывается с `Pooling=false` — иначе перенос снимка в облачную очередь (`File.Move`) и удаление при ротации падали с «файл занят другим процессом»

## [1.3.0] - 2026-07-31

### Добавлено
- Погашение кредитных карт: операция-погашение с FIFO-распределением суммы по покупкам и системной категорией «Погашение кредита»
- Экран погашения кредитной карты с выбором суммы, типа оплаты и даты
- Полнотекстовый поиск по описаниям операций на SQLite FTS5: регистронезависимый, в том числе для кириллицы, с точным количеством результатов и корректной пагинацией
- `tools/DocValidator`: реализованы `ModelValidator` и `ViewModelValidator` для сверки сущностей и ViewModel с JSON-справочниками.
- `tools/DocValidator`: реализован `TrapSyncValidator` для сверки `TRAPS.md` и `json/traps.json`.
- Тесты для `ModelScanner`, `ViewModelScanner`, `ModelValidator` и `ViewModelValidator`.
- Тесты для `TrapMarkdownParser` и `TrapSyncValidator`.
- CI: добавлен job `docs` с запуском `DocValidator`, проверкой JSON (`jq`) и Markdown-ссылок (`lychee`).

### Изменено
- Сверка кассы и отчёт «Баланс за период»: кредитный долг рассчитывается на дату сверки, а не на текущий момент
- Отчёт по долгам: итоги «Нам должны» / «Мы должны» учитывают только активные долги
- Импорт настроек: значения валидируются и нормализуются к допустимым диапазонам
- Внутренняя архитектура: декомпозиция дашборда, операций и настроек на отдельные сервисы; общая логика отчётов вынесена в базовый класс `BaseReportViewModel`
- Валидация форм паролей переведена на единый механизм `INotifyDataErrorInfo`

### Исправлено
- Крах расчёта даты следующего платежа по кредитной карте с днём платежа 29–31 в коротких месяцах
- Крах отчёта по долгам при вызове без даты окончания периода
- Восстановление операции (soft delete) теперь атомарно восстанавливает связанные покупки и погашения
- Поиск по описанию на больших объёмах больше не теряет результаты (ранее действовал лимит 5000 записей)
- Кнопки «Изменить»/«Удалить» корректно обновляют доступность при смене выбранной операции
- `docs/kimi/json/viewmodels.json`: `DebtRepaymentViewModel` помечен как `registeredInDi: false` (создаётся вручную в `DebtReportViewModel`).
- `docs/kimi/TRAPS.md`: раздел 5 приведён к формату `### N.N.` для синхронизации с `json/traps.json`.
- `.github/workflows/ci.yml`: обновлена версия .NET для `build-and-test` с `8.0.x` на `10.0.x`.

## [1.2.0] - 2026-06-28

### Добавлено
- Модуль учёта долгов: дебиторская и кредиторская задолженность с контрагентами
- Справочник контрагентов с типами (клиент, филиал, поставщик, прочее)
- Создание долговых операций из окна редактирования операции
- Окно погашения долга с выбором суммы, типа оплаты и даты
- Отчёт по долгам с фильтрами, группировкой по дням и экспортом в PDF/Excel
- Статусы долгов: активный, погашённый, списанный
- Автоматический пересчёт статуса долга после погашения или удаления погашения

### Изменено
- Операции создания долга скрыты из общего списка операций; отображаются только операции-погашения
- Обновлён дизайн списка долгов в отчёте по долгам

## [1.1.0] - 2026-06-14

### Добавлено
- Модуль кредитных карт: учёт карт, лимитов, процентной ставки, минимальных платежей и покупок
- Оплата операций с помощью кредитной карты и учёт кредитного долга
- Виджет кредитных карт на дашборде с остатком лимита и ближайшим платежом
- Окно «Сверка кассы» с отображением наличных, безналичных, кредитного долга, фактического и чистого баланса на выбранную дату
- Навигация на экран сверки через боковое меню и горячую клавишу Alt+5
- В отчёте баланса отдельные карточки «Деньги» / «Кредит» и «Чистый баланс» с датой следующего платежа

### Изменено
- Кредитные операции больше не влияют на текущий наличный баланс на дашборде
- Обновлён дизайн списка кредитных карт и окна редактирования карты

## [1.0.2] - 2026-06-05

### Оптимизация
- Перевод `TransactionService` и `CategoryService` на `IDbContextFactory<AppDbContext>` — устранены утечки отслеживания EF Core и конфликты при долгоживущих ViewModel
- Кеширование `SolidColorBrush` в конвертерах цветов (`ConcurrentDictionary` + `Freeze`) — снижение нагрузки на GC при обновлении списков
- Оптимистичное обновление UI (`OptimisticAddTransaction`) — мгновенное отображение добавленной операции без ожидания полной перезагрузки данных
- Пересоздание `ObservableCollection` вместо поэлементного `Clear`/`Add` в `TransactionsViewModel` и `DashboardViewModel` — устранены лишние перестройки UI
- Тяжёлые операции группировки и агрегации перенесены в пул потоков (`Task.Run`)
- Уменьшена задержка debounce при поиске и фильтрации с 50 мс до 1 мс

### Исправлено
- Исправлен race condition при сохранении операции — двойной клик по кнопке «Сохранить» больше не создаёт дубликатов (флаг `_isSaving` + блокировка команд)
- Устранён конфликт отслеживания `Category` при редактировании операции и категории (использование фабрики контекстов вместо scoped `DbContext`)
- Исправлена асинхронность обработчиков `OnSaved` / `OnSavedKeepOpen` для предотвращения состояний гонки

## [1.0.1] - 2025-05-30

### Добавлено
- Shift+Enter для добавления следующей операции без закрытия окна
- Отображение прибыли (разницы доходов и расходов) в отчёте баланса

### Исправлено
- Конфликт отслеживания `Category` при редактировании операции

## [1.0.0] - 2025-05-28

### Добавлено
- Главный дашборд с балансом, доходами, расходами и топом категорий
- Управление операциями (доходы/расходы) с фильтрацией и поиском
- Управление категориями с цветами и сортировкой
- Отчёты: баланс за период, структура по категориям, детализация операций
- Экспорт отчётов в PDF и Excel
- Защита паролем с автоблокировкой экрана
- Восстановление пароля через секретный вопрос
- Резервное копирование базы данных
- Импорт/экспорт настроек в JSON
- Тёмная и светлая темы оформления
- Портативная сборка (ZIP)
- Полный набор юнит-тестов (xUnit)
