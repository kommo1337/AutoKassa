# AutoKassa — Traps Summary

> Короткая выжимка [`docs/kimi/TRAPS.md`](../../../../docs/kimi/TRAPS.md). Используй как шпаргалку внутри skill `autokassa`.

## Архитектурные запреты
1. **Не пиши бизнес-логику в code-behind View.**
2. **Не используй статический Service Locator.** Нет `App.GetService<T>()` — не добавляй.
3. **Не делай синхронных запросов к БД.** Никаких `.Result`, `.Wait()`, синхронных `ToList`/`SaveChanges`.
4. **ViewModel не работает напрямую с DbContext.** Только через сервисы.
5. **Не вызывай долгие операции в конструкторе сервисов.** Особенно Singleton.

## Бизнес-правила-ловушки
- Только soft delete (`IsDeleted = true`).
- `PaymentType.Debt` не влияет на баланс.
- Системные категории (`IsSystem = true`) нельзя удалять.
- Уникальность названия категории в рамках `OperationType`.
- Нельзя удалить категорию по умолчанию.
- Нельзя редактировать операцию-погашение.
- Нельзя удалить контрагента с операциями.
- Нельзя списать долг с погашениями.
- Нельзя погасить неактивную кредитную карту.
- Погашение кредитной карты — только `Cash` или `NonCash`.
- Нельзя удалить кредитную карту с непогашенным долгом.
- Покупка по карте: активность, лимит, сумма погашения ≤ текущего долга.
- Долговые операции скрыты из списка операций по умолчанию.
- Нельзя создать/обновить операцию с неактивной категорией.
- При смене типа оплаты с долга на обычную удаляются связи с погашениями.
- Погашение долга ≤ остатка.
- Имя контрагента уникально регистронезависимо.
- Не меняй `IsSystem` у существующих категорий.
- `InitialBalance` относится только к наличным.

## Технические ловушки
- SQLite `LOWER()` не поддерживает кириллицу — фильтруй описание в памяти.
- Не добавляй сущности с заполненными навигационными свойствами из другого контекста.
- `AppSettings` — single-row таблица, `Id = 1`.
- Уважай `MaxInMemoryFilterLimit` для текстового поиска.
- `CreditCardPurchase.RemainingDebt` ≥ сумма погашений.
- `CreditCardPayment` удаляются каскадно при удалении `CreditCardPurchase`.
- Настройки кешируются — изменяй только через `SaveSettingsAsync`.
- Путь бэкапа санитизируется.
- Восстановление из бэкапа: `ClearAllPools()` + `MigrateAsync`.
- Группировка по категориям — по `CategoryId`, не по ссылке.
- Уважай `MaxDetailTransactions` / `MaxCategoryTransactions`.

## Частые ошибки
- Забыть вызвать `NotifyDataChanged()`.
- Забыть зарегистрировать сервис/VM в DI.
- Забыть добавить `DataTemplate` в `MainWindow.xaml`.
- Забыть обновить миграцию после изменения модели.
- Забыть отписаться от `IDataChangeService.DataChanged`.
- Забыть обновить документацию и JSON-справочники.
